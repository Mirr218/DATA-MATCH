# Команде: где мы и что делаем дальше

## Что за задача и что сдаём

Прогнозируем итог обычных продаж для 17 матчей «Авангарда» по 8 ценовым зонам: всего 136 чисел. У 6 матчей продажи идут, у 11 не начались; сценарий — ситуация с разным объёмом известной информации. Оценивают RMSE — ошибку в билетах, сильнее наказывающую за крупные промахи; меньше означает лучше.

Сдаём целые прогнозы, воспроизводимый ноутбук — документ с расчётами, инструкцию запуска и презентацию максимум на 10 слайдов. Целевая сдача — 8 октября до 18:00, дедлайн — 23:59 по Омску, UTC+6. Новые эксперименты прекращаем 6 октября, материалы собираем 7 октября.

## Как мы работаем

Baseline — простая точка отсчёта: «купят столько, сколько обычно покупали». Наш вариант берёт среднее по зоне за прошлые доступные матчи. Усложнение должно улучшить результат и оставаться понятным.

Утечка — подсказка из будущего, словно ответ оказался среди условий экзамена. Отсечка — момент прогноза, после которого сведения недоступны. Утром продажи этого дня ещё неизвестны; обучаемся только на завершённых матчах.

Окно проверки — группа матчей для проверки прогноза по более ранней истории. Матчи не перемешиваем, их зоны держим вместе. Все три окна участвуют в выборе: независимого финального экзамена среди них нет.

Критерии принятия фиксируем заранее. Журнал сохраняет гипотезу, условия, числа и решение, включая неудачи.

Цикл сессии:

- Читаем текущее состояние и правила.
- Записываем гипотезу и список кандидатов до расчётов.
- Проверяем, какие сведения доступны в момент прогноза.
- Делаем небольшое изменение и сравниваем с baseline.
- Проверяем утечки и обсуждаем результат.
- Записываем решение и следующий шаг.

## Что уже сделано

Данные проверены, факты исправлены, догадки отделены от доказанного. Собрана таблица из 680 пар «матч — зона» и проверка на окнах M035–M051, M052–M068, M069–M085. Далее числа идут в этом порядке.

Исходное среднее воспроизвело RMSE 155.999 / 103.139 / 157.144. Методы сравниваем по уточнённой схеме с отсечками и сценариями.

RMSE без продаж: 155.995 / 105.410 / 157.123. С продажами: 151.394 / 102.931 / 132.333. Отличия объясняются округлением, доступной историей и составом примеров.

R — ошибка окна: смешиваем квадраты ошибок сценариев с весами 11/17 и 6/17, извлекаем корень. R = 154.386 / 104.542 / 148.846. S — общая оценка, среднее R с весами 0.25 / 0.25 / 0.50; сейчас S = 139.155.

Принятие модели требует одновременно S ≤ 136.37, улучшения R минимум в двух окнах и последнего R ≤ 153.31. Оценки сценариев S[0] = 143.913, S[1] = 129.748; пределы — 148.23 и 133.64. Ориентиры округлены: решаем по полным числам, исходным правилам улучшения минимум на 2% и допустимого ухудшения максимум на 3%.

С продажами проверяем 10 / 17 / 9 матчей с периодом от 28 дней. Отсечки — через 27 и 7 дней от открытия, веса внутри пары — 2/3 и 1/3: матчи равновесны. Нижняя граница запрещает прогноз меньше уже проданного.

Граница уменьшила RMSE на 0.288 / 0.782 / 16.376; состав выборки объясняет ещё 4.312 / 0 / 8.414, поздняя доступная история — 0 / 1.697 / 0. Главные ошибки у зоны 6, в последнем окне велика и ошибка зоны 7; причины изменений спроса неизвестны.

Потолок — максимум обычных билетов: места за вычетом абонементов. Исторический пока только описывает данные: его доступность на отсечку не доказана, в проверке не применяем. Предоставленный потолок тестовых матчей обязателен.

Файл baseline сохранён. Проверены 136 целых чисел по шаблону: граница подняла 3 строки, потолок обрезал 0. Зафиксированы 19 успешных тестов и повторяемость сборки; точность на неизвестных ответах пока неизвестна.

evaluate_method принимает метод, прошлые итоги и общие проверочные примеры. Сам метод получает доступную историю и строки для прогноза, возвращает числа в том же порядке. Проверка отдаёт ошибки по окнам, сценариям, зонам и отдельным прогнозам; отдельная функция собирает R/S.

Пример подключения воспроизводит сценарные числа выше. Нельзя менять правила, порядок ответов, учиться на проверочных итогах или переносить обученное состояние между вызовами. Ноутбук, инструкция и презентация не собраны; новые модели не проверены.

## Словарик

- RMSE — ошибка в билетах, особенно чувствительная к большим промахам.
- Baseline — простой прогноз для сравнения.
- Окно проверки — группа матчей для проверки по прошлому.
- Утечка — использование сведений из будущего.
- Отсечка — граница доступной информации во времени.
- Сценарий — ситуация с продажами или без.
- Потолок — максимально допустимое число обычных билетов.
- R — объединённая ошибка сценариев в одном окне.
- S — итоговая оценка по всем окнам для выбора метода.
- Признак — подсказка, например день недели.


## Карта файлов и порядок чтения

Порядок: обзор → AGENTS → STATE → PROTOCOL → HOWTO_EVALUATE → последние EXPERIMENTS; перед данными — DATA_FACTS. Первое знакомство — примерно 30 минут: авторская оценка, не измерение. Аудиты — по необходимости.

Каждая строка: назначение; когда читать; главное; что отложить.

- `docs/STATE.md` — статус; перед сессией; готовое и открытое; расположение старой копии.
- `docs/PROTOCOL.md` — оценка; до моделей; отсечки и критерии; ограничения не пропускать. Меняет только человек либо агент по отдельному поручению.
- `docs/HOWTO_EVALUATE.md` — подключение; перед кодом; интерфейс и контроль; пример при обзорном чтении.
- `docs/EXPERIMENTS.md` — журнал лидера; перед сравнением; последние решения; старые реализации.
- `docs/DATA_FACTS.md` — исправленные факты; перед данными; цель и гипотезы; детальные распределения.
- `docs/DATA_FACTS_AUDIT.md` — доказательства; при сомнениях; нужное утверждение; остальные строки. «НЕТ» относится к исходной версии.
- `docs/BASELINE_SCENARIOS_AUDIT.md` — аудит сценариев; для истории; область проверки; старые детали.
- `docs/BASELINE_SUBMISSION_AUDIT.md` — аудит сборки; перед сдачей; формат и границы; старые номера строк.
- `docs/LEAKAGE_AUDIT_FINAL.md` — итоговый аудит; перед использованием результатов; вердикт; подробные доказательства.
- `docs/TEAM_BRIEF.md` — обзор; новичку; задача и готовое; знакомые термины.
- `docs/NEXT_SESSION.md` — план; перед работой; гипотезы и остановка; промпт до запуска сессии.
- `src/baseline_data.py` — загрузка; перед данными; load_training_table; реализация.
- `src/validation.py` — проверка лидера; при подключении; описание evaluate_method; внутренние проверки.
- `src/scenarios.py` — примеры; перед признаками; отсечки и ограничения; детали сборки.
- `src/baseline.py` — среднее; перед кандидатом; zone_mean_baseline; отдельный исходный запуск.
- `src/evaluate_baseline.py` — оценка; при повторении; общий вызов; запись результатов.
- `src/diagnose_baseline.py` — диагностика; при интерпретации; одинаковые выборки; сохранение файлов.
- `src/make_baseline.py` — сборка; перед сдачей; границы и шаблон; техническая запись.
- `src/check_facts.py` — проверка утверждений; при расхождении; нужная проверка; остальные блоки.
