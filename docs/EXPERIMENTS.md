- Пригодный аналог: идентификатор и зона есть только в переданной history; матч до начала проверочного окна и завершён строго до календарного дня C; историческая отсечка не раньше открытия и строго раньше исторического матча; исторический полный итог больше нуля. Историю и доли определяем заново при каждом вызове, без обученного состояния между вызовами.

### №10, 2026-10-06, лидер конвейера — гипотеза и кандидат C до расчётов

Кандидат C:
1. Аналоги только среди завершённых матчей с окном продаж не короче 28 дней и только из переданной history.
2. Этап сравнения по точной доле пройденного окна k/L, без округления самой доли. L = разность дат между sales_open и датой матча, одинаково для проверяемого матча и аналогов; k = число календарных дат продаж до утра отсечки, включая дни с нулём продаж. Продажи дня отсечки исключаются. Для аналога с длиной L_a день от открытия вычисляется с .5 вверх явно: floor(k * L_a / L + 0.5), либо точно целочисленно (2*k*L_a + L) // (2*L), без round() Python. Полученный день ограничивается диапазоном [1, L_a − 1]; сохраняется число случаев, где это ограничение сработало.
3. Множитель m = сумма продаж по 8 зонам к отсечке / сумма по зонам средних продаж аналогов на том же этапе.
4. m ограничивается интервалом [0.5, 2].
5. Прогноз зоны = baseline_зоны × (1 + 0.5 × (m − 1)).
6. Нижняя граница «уже продано» и верхняя граница seats зоны.
7. Если аналогов меньше 5, возврат к baseline.

Параметры 0.5, [0.5, 2], 5 не подбирать.
