# Протокол проверки

Владелец документа — человек. Первоначальное создание выполнено по его явному поручению; последующие изменения агентом запрещены без отдельного явного разрешения.

## Моменты прогнозов и честная проверка
Для всех 17 test момент прогноза — утро 15.12.2025, продажи известны по 14.12 включительно; КХЛ только по 19.11.2025.
- 11 без продаж (M092–M102): календарь, соперники, sales_open, предоставленные параметры зон, история завершённых матчей; своих продаж ещё нет. Прогнозируем весь итог.
- 6 с продажами (M086–M091): то же плюс собственные продажи по 14.12. Прогнозируем полный итог вместе с уже проданным.
Историческому примеру назначается аналогичный момент прогноза. Итоги для обучения должны относиться к завершённым к этому моменту матчам, а признаки — к известной тогда информации. Все зоны одного матча находятся в одной части. Никаких случайных разбиений, внешних данных и подглядывания поздних продаж.
Окна: M035–M051, M052–M068, M069–M085. Все три участвуют в выборе; последнее не объявляется независимым финальным тестом. До сравнения методов фиксируются исторические срезы, состав примеров и правила усреднения; методы сравниваются на одинаковых примерах. Повторные срезы одного матча не должны произвольно увеличивать его вес.

## Точная оценка и заранее заданные критерии
Обозначения: w = 1, 2, 3 — окно; s = 0 — без продаж, s = 1 — с продажами. MSE[w,s] — средний квадрат ошибки в билетах по фиксированным примерам сценария в окне, со всеми восемью зонами. При повторных срезах сначала усреднять ошибки внутри пары матч–зона, затем между парами, чтобы каждый матч имел одинаковый вес.
Общая ошибка окна: R[w] = sqrt((11/17) * MSE[w,0] + (6/17) * MSE[w,1]). Смешиваются квадраты ошибок, а не готовые RMSE сценариев.
**S = 0.25 * R[1] + 0.25 * R[2] + 0.50 * R[3].** Это взвешенное среднее трёх объединённых RMSE окон, а не корень из среднего по трём окнам.
Отдельная оценка сценария: S[s] = 0.25 * sqrt(MSE[1,s]) + 0.25 * sqrt(MSE[2,s]) + 0.50 * sqrt(MSE[3,s]).
Кандидат заменяет текущий принятый вариант, если одновременно:
1. S уменьшается не менее чем на 2%.
2. Общая R[w] улучшается минимум в двух из трёх окон.
3. Общая R[3] ухудшается не более чем на 3%.
4. Ни один сценарий не ухудшается по своей S[s] более чем на **3%**. Если исходная ошибка равна нулю, разрешено только нулевое значение кандидата.
Пороги — предварительные инженерные правила, а не доказательство статистической значимости. Их не подстраивать после просмотра экспериментов. При меньшем выигрыше сохранять более простой вариант. В отчёте показывать обе сценарные ошибки каждого окна, R[w] и S, а также сравнение с исходным baseline. Одинаково применять ограничения и округление итогов ко всем сравниваемым методам; недоступные исторические ограничения не подставлять из будущего.

## Выравнивание для шести матчей с продажами
Сравнить два способа: (а) одинаковое число дней до матча; (б) одинаковое число календарных дней продаж с открытия. Для M086–M089 доступны 27 дней включительно, до матчей 10/12/14/16 дней; для M090–M091 доступны 7 дней включительно, до матчей 30/32 дня. Не путать число календарных дат и разность дат.
Для M090–M091 первоначально предпочтительна гипотеза первых семи дней: при сопоставлении по 30/32 оставшимся дням исторические продажи часто ещё не открыты. Но при коротком периоде продаж первая неделя может быть почти финалом, поэтому учитывать и прошедший, и оставшийся срок.
Train имеет окна продаж 10–63 дня, test — 28–42. Отдельно проверить похожие исторические периоды 28–42 дня и сообщать объём этой выборки. Не выбирать победителя на разных выборках. Если исторический матч уже состоялся к нужному дню с открытия, такой пример не подходит; правила покрытия фиксировать до сравнения. Если оба способа плохо проверяются на достаточном числе примеров, сохранить более простой baseline.

## Зафиксированные срезы сценария с продажами (шаг 4, 04.10.2026)
Записано по явному поручению человека в шаге 4. Правило действует одинаково для baseline и кандидатов; формулы R, S и пороги выбора выше не изменяются.

O — дата sales_open, D — дата матча. Длительность окна продаж определяем как разность дат L = (D − O).days, без добавления единицы. В каждом проверочном окне выбираем только матчи с L ≥ 28. Это общая выборка для ОБОИХ срезов: короткие матчи не добавляем отдельно в семидневный срез. Все восемь зон выбранного матча участвуют в обоих срезах.

| Срез | Момент прогноза | Доступные дневные продажи | Вес внутри пары матч–зона |
|---|---|---|---:|
| 27 дней | утро O + 27 дней | даты O…O + 26 включительно | 2/3 |
| 7 дней | утро O + 7 дней | даты O…O + 6 включительно | 1/3 |

Считаем календарные дни, включая дни с нулём продаж. Отсечка не включает продажи самого дня прогноза. Оба момента строго раньше даты матча; если это условие нарушено, пример не подходит.

Пусть e27[m,z] и e7[m,z] — ошибки прогноза полного итога в двух срезах пары (m,z), после общих ограничений и согласованного округления. Сначала получаем E[m,z] = (2/3) * e27[m,z]^2 + (1/3) * e7[m,z]^2, затем MSE[w,1] = среднее E[m,z] по всем выбранным матчам окна и восьми зонам. RMSE[w,1] = sqrt(MSE[w,1]). Это смешивание 4:2 внутри каждой пары, а не удвоение количества матчей. Сумма весов срезов каждой пары равна 1, поэтому каждый выбранный матч имеет одинаковый общий вес. На этой общей выборке формула также равна (2/3) * MSE27 + (1/3) * MSE7; нельзя переносить её на разные составы матчей.

Нижняя граница baseline с продажами: max(0, уже продано на отсечку), где уже продано = сумма tickets только за доступные даты этой пары матч–зона. Полный исторический итог остаётся правильным ответом для оценки и не используется как граница. То же правило применяется к кандидатам.

Обучающая история состоит только из матчей ДО первого матча проверочного окна, завершённых до календарного дня конкретного момента прогноза. Проверочные матчи окна не входят в обучение ни при одном срезе, даже если к более позднему срезу они завершились. Доступную часть истории определяем отдельно для каждой отсечки; окончательные итоги ещё не завершённых матчей исключаем.

Состав проверен по matches.csv 04.10.2026, без запуска моделей:

| Окно | Подходящие матчи для обоих срезов | Матчей | Пар матч–зона на срез | Из них L в диапазоне 28–42 |
|---|---|---:|---:|---:|
| M035–M051 | M039, M043–M051 | 10 | 80 | 10 |
| M052–M068 | M052–M068 | 17 | 136 | 12 |
| M069–M085 | M076, M078–M085 | 9 | 72 | 9 |

Диапазон 28–42 — диагностическая подвыборка, а не дополнительное условие основной оценки. Основная общая выборка остаётся L ≥ 28. Исторический потолок и округление согласованы в разделе «Ограничения при оценке» ниже.

## Контракт признаков
Каждый признак считается функцией, которой передаётся дата отсечки (момент прогноза) для каждого матча. Функция использует только сведения, доступные на эту дату, а не просто раньше даты матча.
У каждого признака в коде есть комментарий `доступен на момент: ...`, описывающий источник и границу доступности. Заранее известное расписание допустимо; будущие продажи и результаты игр недопустимы. Для утреннего среза дневные продажи известны лишь по предыдущий день включительно.
Для КХЛ историческая информация замораживается на 26 дней относительно момента прогноза; в одном срезе используется одна дата заморозки для всех будущих матчей. Пользу проверять относительно варианта без КХЛ. В test фактическая граница — 19.11.2025.
Данные абонементов должны быть известны на отсечку и относиться именно к нужному матчу. Возможность восстановления через package_matches ещё не установлена.
До подтверждения командой календарь государственных праздников России не используется, хотя считается общедоступной информацией. Пока допустимы вычисляемые из даты признаки: день недели, месяц, номер матча в сезоне по известному расписанию, дни до Нового года. Остальные внешние данные запрещены.

## Ограничения при оценке
Нижняя граница прогноза — ноль. В сценарии с продажами нижняя граница — сумма tickets, наблюдаемая на отсечку для этой пары матч–зона; поздние продажи и полный исторический итог в неё не входят. Ограничение одинаково для baseline и кандидатов.
Исторический потолок: **04.10.2026 человек подтвердил проверку без верхнего ограничения, пока его доступность на отсечку не доказана**. В текущей исторической оценке baseline и кандидатов окончательные seats − season_tickets не применяются. Подстановка окончательных исторических абонементов из будущего запрещена. Изменение этого общего правила после доказательства доступности требует отдельного согласования и одинакового применения ко всем сравниваемым методам.
Вопрос связан также с целью «доля заполнения»: не начинать это сравнение до решения о доступности знаменателя. Финальные ограничения test по предоставленному zones остаются обязательными, как указано выше; решение об исторической проверке их не отменяет.

Округление: **04.10.2026 человек подтвердил ближайшее целое, ровно .5 — вверх, затем применение границ**. Для конечного числового прогноза p используем floor(p + 0.5), затем нижнюю границу 0 в сценарии без продаж или max(0, уже продано на отсечку) в сценарии с продажами. Исторического верхнего ограничения сейчас нет. В test после того же округления применяем обязательные нижнюю границу уже проданного и верхнюю seats − season_tickets; если нижняя граница выше верхней, сообщить о противоречии и остановить сборку файла. Правило одинаково для всех методов в сценарной оценке и сдаваемом файле. Исходный арифметический ориентир шага 3 сохраняется без округления и не является сценарной оценкой R/S.
